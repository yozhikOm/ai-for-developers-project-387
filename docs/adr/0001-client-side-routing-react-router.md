# Клиентский роутинг через react-router-dom

Frontend был чистым каркасом без роутинга, но backend (`apps/api/src/app.ts`) уже
содержит SPA-fallback: неизвестные GET-запросы отдают `index.html`, то есть
серверная часть заранее рассчитана на несколько клиентских маршрутов. Вместо
самодельной навигации (condition rendering, ручной `history`) выбрали
`react-router-dom` как стандартное решение для этого случая — с появлением
страницы записи (`/booking`) кроме главной (`/`) ручное решение не давало бы
выигрыша, но требовало бы больше кода для тех же гарантий.
