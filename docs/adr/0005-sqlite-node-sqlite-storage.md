# Хранение в SQLite через встроенный `node:sqlite`

EventType и Booking хранятся в файле SQLite, доступ — встроенный модуль Node
`node:sqlite` (`DatabaseSync`): данные переживают перезапуск сервера, а новых
npm-зависимостей и нативной сборки не нужно. В Node 24.21 модуль работает без
флага и без `ExperimentalWarning`, но официально ещё не stable — это осознанный
риск ради нулевых зависимостей. Решение принято в тикете
[Хранение данных](https://github.com/yozhikOm/ai-for-developers-project-386/issues/17).

## Considered Options

- **Память процесса**: проще всего, но данные Owner теряются при каждом
  перезапуске.
- **`better-sqlite3`**: зрелый, но нативный модуль — сборка в Docker на Alpine и
  лишняя зависимость при наличии встроенного аналога.
- **Внешняя СУБД (Postgres)**: отдельный сервис, драйвер и docker-compose —
  несоразмерно одному Owner и окну в 14 дней.

## Consequences

- Путь к файлу — `DATABASE_PATH`, по умолчанию `data/calendar.db` (`data/` в
  `.gitignore`). В Docker — `/app/data`, каталог принадлежит пользователю `node`;
  `docker:run` монтирует именованный volume, иначе данные живут только до
  удаления контейнера.
- Схема — миграции в коде, номер применённой хранится в `PRAGMA user_version`;
  при старте недостающие применяются, каждая в своей транзакции.
  `PRAGMA foreign_keys = ON`.
- id — UUID (`crypto.randomUUID()`, TEXT); моменты времени — INTEGER, мс с
  эпохи (UTC).
- Атомарность «проверить правила → создать Booking»: проверка и `INSERT` в
  `BEGIN IMMEDIATE … COMMIT` одним синхронным участком, без `await` между ними.
  Пересечение интервалов с учётом Buffer индексом не выразить, поэтому гарантию
  даёт транзакция, а не ограничение схемы.
- `buildApp({ databasePath = ':memory:', now })`: по умолчанию у каждого
  инстанса своя БД в памяти, поэтому тесты через `app.inject()` изолированы и не
  трогают диск; соединение закрывается в `onClose`. Прод (`index.ts`) передаёт
  `DATABASE_PATH`.
- Засев (два EventType: 15 и 30 минут) включает `index.ts` флагом
  `buildApp({ seedNewDatabase: true })`, и выполняется он только при создании
  новой БД (до открытия `user_version = 0`). По умолчанию `buildApp()` ничего не
  засевает. Флаг нужен потому, что признак «БД новая» известен только при её
  открытии, а засев проверяется тестом через фабрику с временным файлом БД.
