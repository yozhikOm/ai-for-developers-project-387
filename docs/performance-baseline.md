# Performance baseline (LCP, CLS, INP)

Исходный baseline web-vitals главной страницы, зафиксирован по отчёту
Lighthouse от 2026-10-14. Сам файл `lighthouse-report.json` — артефакт запуска
воркфлоу `.github/workflows/opencode-lighthouse.yml`: он создаётся в CI, в
репозиторий не коммитится (в `.gitignore`) и хранится как artifact запуска.
Заведён по тикету
[#11](https://github.com/yozhikOm/ai-for-developers-project-387/issues/11).
При следующих замерах значения сравниваются с этим baseline по правилу из
раздела «Правило сравнения».

## Условия замера

- URL: https://ai-for-developers-project-386-og4b.onrender.com/
- Дата: 2026-10-14T11:01:29Z
- Lighthouse 13.5.0, navigation mode, мобильная эмуляция (moto g power 2022),
  benchmarkIndex 2356

## Baseline

| Метрика | Значение | Оценка Lighthouse | Порог «хорошо» (web.dev) |
| --- | --- | --- | --- |
| LCP | **1955 мс** (2.0 s) | 0.97 | ≤ 2500 мс |
| CLS | **0.061** | 0.97 | ≤ 0.1 |
| INP | **нет лабораторного значения** (см. ниже) | — | ≤ 200 мс |
| TBT (временный прокси INP) | **682 мс** | 0.44 | — |

## INP: временный лабораторный прокси — TBT

INP — метрика взаимодействия, лабораторный прогон Lighthouse её не измеряет
(`inp-breakdown-insight` → `notApplicable`). До появления полевых данных (RUM)
лабораторным прокси служит **Total Blocking Time: 682 мс** (оценка 0.44, самое
слабое место отчёта: одна длинная задача ~146 мс при исполнении
`index--E0RNfuc.js`, ~879 мс script evaluation).

TBT **не заменяет полевой INP**: как только появятся RUM-данные, baseline по
INP нужно зафиксировать отдельно по ним, а прокси убрать.

## Правило сравнения

- Регрессия — деградация любой метрики более чем на **10%** от baseline.
- При регрессии > 10% заводится issue.
- Шум замеров: контрольный прогон того же кода 2026-10-14T11:21:32Z
  (URL https://ai-for-developers-project-387-by33.onrender.com/,
  benchmarkIndex 1545.5) дал LCP 1964 мс (+0.5%), CLS 0 (−100%),
  TBT 493 мс (−28%). Шумные метрики (TBT, CLS) гуляют между прогонами,
  поэтому 10% — разумный минимум порога, а решение о регрессии по TBT/CLS
  принимать по нескольким прогонам или по медиане, иначе будут ложные
  срабатывания.
